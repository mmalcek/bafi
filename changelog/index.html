Changelog

Release notes for bafi. Each release is a level-2 heading (## X.Y.Z) matching version.txt. task release extracts the matching section as the GitHub release body and refuses to tag if the section is missing. Newest release first.

1.4.0

Security

  • Lua sandbox. The Lua state no longer exposes os.execute, os.exit, os.remove, os.rename, os.tmpname and io.popen. Everything else in the Lua standard library (os.date, os.time, io.open, require, ...) works as before. If your functions.lua shelled out through one of the removed functions, it will now fail with luaError: ... attempt to call a non-function object.
  • Lazy Lua loading. ./lua/functions.lua is loaded the first time a template calls {{lua ...}}, not at startup. bafi -v, bafi -h and templates that do not use Lua never execute code from the current directory.
  • OpenAI key from the environment. The API key is read from OPENAI_API_KEY when -gk is not given, so it no longer has to appear in process listings and shell history. -gk still works and overrides the variable.
  • CI hardening. All GitHub Actions are pinned by commit SHA, workflows declare minimal permissions, deprecated action versions are upgraded (checkout v7, setup-go v7, setup-python v7, CodeQL v4) and a govulncheck job runs on every push. Dependabot keeps the pins current.
  • Release pipeline rebuilt. Releases are built on the GitHub runner with the Go version from go.mod (task dist) instead of the go-release.action Docker image. gofmt/vet, tests and govulncheck gate the release, every asset is listed in a SHA256SUMS.txt, and the release notes are the matching CHANGELOG.md section.
  • go.mongodb.org/mongo-driver bumped to v1.17.10 (GO-2026-5327; the affected GSSAPI code was never reachable from bafi).
  • Minimum Go raised to 1.27.2 (go.mod), the release that fixes the stdlib advisories GO-2026-6603 … GO-2026-6617 reported by govulncheck. Release binaries are built with the same version.
  • Release archives: new darwin_arm64 (Apple silicon) and linux_arm64 builds next to the existing windows_amd64, linux_amd64, linux_386 and darwin_amd64. The per-asset MD5 _checksum.txt files are replaced by one SHA256SUMS.txt.
  • task release only tags and pushes; the GitHub release is created by CI.
  • New ## Security notes section in the documentation (trusted templates, no output escaping, CSV formula injection, OpenAI data sharing, randInt).

Added

  • csvSafe template function: prefixes values starting with =, +, -, @, TAB or CR with ' to defuse spreadsheet formula injection. Plain numbers such as -5 are left untouched.

Fixed

  • Lua functions returning a non-string leaked one value on the Lua stack per call.
  • A missing or broken ./lua/functions.lua, or a non-string function name, now yields an inline luaError: in the output instead of aborting the whole run.
  • Unicode CSV delimiters (-d) are handled correctly (PR #13).
  • A malformed -i ?files.yaml record (wrong type or missing file/label) is reported as fileList[<index>]: ... instead of crashing with a stack trace.
  • An invalid hex CSV delimiter (-d 0xZZ) is reported as mapCSV: invalid delimiter through the normal error path instead of log.Fatalf.
  • toXML renders []interface{} slices (e.g. from mustArray or nested JSON arrays) as <record> elements instead of failing on a type assertion.
  • randInt cannot overflow on extreme bounds such as {{randInt 0 9223372036854775807}}.
  • An invalid pattern in replaceAllRegex aborts the template with a readable error calling replaceAllRegex: error parsing regexp: ... instead of a recovered panic.
  • An OpenAI response without choices is reported as an error instead of a panic.

Changed

  • -gq alone now selects OpenAI mode (key from -gk or OPENAI_API_KEY). Without any key it fails with OpenAI API key must be defined instead of being silently ignored.
  • format in the -i ?files.yaml file list is optional; it is detected from the file extension when omitted, exactly like for a single -i file.
  • randInt uses math/rand/v2; the explicit rand.Seed at startup is gone (the generator is auto-seeded since Go 1.20).
  • Version is read from version.txt (embedded at build time) instead of a constant in main.go.
  • New Taskfile.yml with task build|test|vet|check|vuln|docs|release|clean. task release tags, pushes and publishes the GitHub release that triggers the CI build.
  • The changelog is part of the documentation site.
  • CI release build runs only on published releases (PR #12).
